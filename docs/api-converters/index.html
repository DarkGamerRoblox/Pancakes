Custom converters

Teach Pancakes how to write and reconstruct a metatable-backed value.

2 min readRoblox Luau

RegisterConverter#

Register a metatable with a pair of binary callbacks.

Signature
Luau
Pancakes.RegisterConverter(
    classMetatable: {any},
    writeFn: Pancakes.ConverterWriteFn,
    readFn: Pancakes.ConverterReadFn
): ()

The writer receives a borrowed Writer and the value. The reader receives a borrowed Reader and returns the reconstructed value. The callbacks must read and write in exactly the same order.

IDs are assigned sequentially from 1; at most 65535 converters can be registered. Duplicate metatables throw. Register all peers in the same deterministic order before encoding or decoding.

Callback contract#

Callback types
Luau
type ConverterWriteFn = (writer: Pancakes.Writer, value: any) -> ()
type ConverterReadFn = (reader: Pancakes.Reader) -> any
  • Use public colon methods such as writer:WriteU16(value) and reader:ReadU16().
  • Do not yield or re-enter the top-level serializer inside a converter; message caches are shared runtime state.
  • Do not retain, release, or finalize the borrowed Reader/Writer; the enclosing serializer owns its lifecycle.
  • Validate lengths and semantic constraints in the converter. Bounds checking alone does not validate the meaning of your custom format.

UnregisterAllConverters#

Clear registered metatables, numeric converter IDs, and the converter counter.

Signature
Luau
Pancakes.UnregisterAllConverters(): ()
Coordinate registry changes

Existing Auto buffers refer to numeric converter IDs. Cached custom schemas can also retain callbacks. Do not clear or reorder registrations while affected schemas or messages remain in use.
