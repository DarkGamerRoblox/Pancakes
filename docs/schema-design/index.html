Schema design

Make the layout explicit, keep it reusable, and choose field widths that match your application.

2 min readRoblox Luau

Declare schemas once#

Reusable layout
Luau
local Field = Pancakes.Field

local itemSchema: Pancakes.Schema = {
    Field.String("id"),
    Field.U32("amount"),
    Field.Optional(Field.String("nickname")),
}

-- Reuse itemSchema for every write and read.
local encoded: buffer = Pancakes.SerializeSchema({
    id = "Honey",
    amount = 12,
}, itemSchema)

Compilation is cached using the schema table as the key. Do not modify fields or nested schemas after use; create a new schema object for a different format. CompileSchema can warm that cache, but serialize calls still receive the original Schema.

Choose numeric fields#

Pick fixed-width integers only for values that your application validates into range. Use AdaptiveNumber for varied numbers, F32 when precision loss is acceptable, or F64 for double precision.

FieldValid integer range
U80…255
I8−128…127
U160…65535
I16−32768…32767
U320…4294967295
I32−2147483648…2147483647

U64 and I64 still take Luau numbers. They do not provide arbitrary-precision integers; exact integer representation is limited by the number type.

Compose containers#

Nested fields
Luau
local inventorySchema: Pancakes.Schema = {
    Field.Array("items", Field.Table("", itemSchema)),
    Field.Dictionary("counts", Field.U32("")),
    Field.Auto("metadata"),
}

The empty element name is intentional: array entries and dictionary values are encoded by their element codec, not looked up under that name. Field.Auto is the runtime-varying field; there is no separate Union constructor in this build.

Know what validation covers#

Validation is not an application validator

schemaValidationEnabled checks missing required fields during Schema writing. It does not establish numeric ranges, permissions, ownership, or the full meaning of a decoded record. Validate those at the application boundary.

An optional field writes presence information and decodes to nil when absent. Undeclared keys are omitted. A schema change requires matching reader updates; the version hash is a mismatch check, not an automatic migration system.
