Serialization modes

Choose a format based on who needs to read the buffer and how stable your data is.

2 min readRoblox Luau

At a glance#

ModeWriter → readerUse it for
AutoSerializeAuto → DeserializeAutoDynamic payloads; independent peers with the same build and configuration.
SchemaSerializeSchema → DeserializeSchemaStable named records with an explicitly shared layout.
SmartSchemasSerialize → DeserializeLocal repeated-shape tracking within a compatible learned instance.
Pair the APIs

The formats are distinct. Serialize() writes a SmartSchemas tag, even when tracking is disabled. Decode that output with Deserialize(), not DeserializeAuto().

Auto: let the values decide#

Auto writes type tags and chooses eligible table codecs at runtime. It supports primitives, nested tables, Roblox datatypes, and registered converters. Repeated strings and table shapes can reduce repeated wire information.

Use Auto to start quickly, or for a field whose supported type can change. Auto does not guarantee the smallest buffer or fastest time for every payload.

Schema: share the layout#

A Schema is an ordered array of Field.* descriptors. Values are written according to that layout; undeclared record keys are omitted. The writer and reader must agree on the schema and any referenced directory mappings.

A single-record Schema payload includes a version hash. Schema-array payloads do not include this version hash, so your surrounding protocol must identify their schema. See the Schema API.

SmartSchemas: local learning#

The default Serialize wrapper forwards to GlobalSmartSchemas. Tables are initially sent as tagged Auto. Repeated shapes are promoted after 20 sightings by default. Promoted schemas live in that SmartSchemas object.

Receiving Auto packets does not teach the receiver

A fresh client, another SmartSchemas object, or a new server boot cannot assume it can decode promoted Schema or Delta packets. Use explicit shared schemas across those boundaries.

Passing an id enables deltas after promotion. The reader needs the matching learned schema, ID, and ordered prior state. Read the complete SmartSchemas reference.
